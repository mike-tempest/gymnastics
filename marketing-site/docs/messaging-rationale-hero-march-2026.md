# Homepage Hero Messaging Rationale

**Date:** 16 March 2026  
**Agent:** swimly-product-marketing  
**Task:** Homepage Hero messaging optimization

## Context

Homepage messaging audit (15 March) identified Hero.astro as functional but not benefit-led. The Before/After comparison section demonstrates strong benefit-led copywriting, but the Hero section was not matching that quality.

## Previous Messaging

**H1:** Swim Club Management Software for UK Swimming Clubs  
**Subheadline:** Complete management service for UK swimming clubs. Simplify membership, automated billing, attendance tracking, and Wavepower compliance in one platform designed for volunteer-run teams.

### Issues

- H1 is generic and functional, not benefit-led or memorable
- Subheadline is a feature dump (membership, billing, attendance, compliance)
- Does not lead with pain relief or outcome
- Positioning framework offers stronger options

## New Messaging (Implemented)

**H1:** The operating system for competitive swimming  
**Subheadline:** Stop drowning in spreadsheets. Start running a club that actually works.

### Rationale for Option A (Methodology-Led)

#### Strategic Alignment

- Matches positioning framework one-liner: "The operating system for competitive swimming"
- Consistent with how we describe ourselves internally
- Differentiating compared to competitors (no one else positions as an "operating system")

#### Messaging Strength

- **Bold and memorable:** "Operating system" is a strong metaphor that resonates with the reality of what Swimly does (coordinates all club functions)
- **Pain-first subheadline:** "Stop drowning in spreadsheets" immediately acknowledges the volunteer committee's reality
- **Outcome promise:** "Start running a club that actually works" delivers the benefit without listing features
- **Tonal match:** Subheadline tone matches the sharp, benefit-led style of the Before/After comparison

#### Differentiation

- Generic competitors say "swim club management software" (exactly what we had before)
- "Operating system" signals platform thinking, not just a collection of features
- Creates curiosity (why "operating system"?) that the rest of the page can answer

## Alternatives Considered

### Option B: Persona-Specific Rotation

- **H1:** (varies by persona)
- **Sub:** e.g. "Stop chasing subs. Start getting paid." (Treasurer)
- **Why not chosen:** Requires A/B testing infrastructure and increases complexity. Good for future optimisation, but Option A is stronger starting point.

### Option C: Outcome-First

- **H1:** Run your swim club with confidence
- **Sub:** Automated billing, digital attendance, Wavepower compliance. Everything your volunteer committee needs in one platform.
- **Why not chosen:** Safe but not differentiating. "Run with confidence" is generic. Subheadline reverts to feature list.

## Expected Impact

- **Conversion improvement:** Stronger benefit-led messaging should improve waitlist signup rate (current baseline: monitor via GSC + Workshop task)
- **Brand positioning:** Establishes Swimly as a platform/ecosystem, not just another feature-complete tool
- **Consistency:** Aligns Hero with positioning framework and Before/After quality

## Monitoring Plan

- Google Search Console: Track homepage engagement metrics
- Workshop task: Monitor conversion rate (waitlist signups / homepage visitors)
- Qualitative feedback: Monitor founding club enquiries for messaging resonance

## Next Steps (Future Optimisation)

- A/B test persona-specific variants (Option B) once we have baseline conversion data
- Consider dynamic headline rotation based on referral source (e.g., Treasurer-led for finance forums)
- Test alternative subheadlines that emphasise different pain points

---

**Decision:** Option A implemented 16 March 2026. Deployed to swimly.uk.
